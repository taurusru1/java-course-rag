## 3. 逐项评估

### 3.1 JavaGuide —— 最适合做知识库主力

- 目录就是课程大纲：`basis`（基础语法、装箱拆箱、重载重写、反射、序列化、SPI）、`collection`（ArrayList/HashMap/ConcurrentHashMap）、`io`（BIO/NIO/AIO）、`concurrent`（线程池、锁、AQS）、`jvm`（内存、GC、类加载）。
- **问答体**：每个小节就是「Q + 详细答案」，天然适合做「问题 → 答案」训练/评测样本，也适合作为问答页的知识来源。
- 文件带 YAML frontmatter（`title/category/description/tag`），解析时要剥掉，否则会被当成正文。
- 许可 Apache-2.0：可再分发，需保留声明与 NOTICE；仍然建议**只下载不入库**，避免仓库体积膨胀。

### 3.2 toBeBetterJavaer —— 结构最像教材，但不能公开分发

- 章节名与课程几乎一一对应：`basic-grammar`、`oo`、`array`、`collection`、`exception`、`io`、`thread`、`string`、`java8`。
- 仓库无 LICENSE 文件，按默认版权「保留所有权利」处理：**只能本地演示，不能进公开仓库、不能随论文附件分发**。
- 体量大（1.28GB，主要是图片），克隆请用 `--depth 1 --filter=blob:none` 或只取 `docs/src` 下的 md。

### 3.3 TheAlgorithms/Java —— 代码语料的最佳来源

- 848 个类，方法级 Javadoc 齐全，正好用来压测 C1：看「代码块是否被切断」「符号元数据是否准确」。
- MIT 许可，保留版权声明即可。
- 天然适合构造「代码检索」评测：给方法注释，找回实现。

### 3.4 题库：公开源都不理想

- 面试题库（JavaGuide、vipstone）是「问答」不是「可判分的题」，转成选择题需要人工改写，质量不可控。
- 竞赛/入门题库（CodeContests、APPS、MBPP）是英文、且无中文课程语境。
- **结论：题库自建**。尚硅谷 1752 题可作为素材（本地），但要逐题改写为 Java 语境；建议先扩到 60 题（选择/判断/填空/编程）。

### 3.5 报错库：没有现成中文数据集

- javac 的中文报错随 JDK 版本与 locale 变化，公开数据集几乎都是英文。
- 现有做法（`scripts/collect_javac_errors.py` 真实编译采集）已是正确路线：目标从 8 类扩到 30–40 类，每条都带真实输出。

## 5. 获取方式

不把第三方内容提交进仓库，用脚本按需拉取到 `data/corpus/java/public/`（已在 `.gitignore`）：

```powershell
.\.venv\Scripts\python.exe scripts\fetch_public_corpus.py --source javaguide
.\.venv\Scripts\python.exe scripts\fetch_public_corpus.py --source algorithms --limit 80
.\.venv\Scripts\python.exe scripts\fetch_public_corpus.py --list
```

脚本会：拉取仓库文件树 → 只下 `docs/java/**/*.md`（或指定 java 目录）→ 剥 YAML frontmatter → 统一加一行来源注释 → 写到 `data/corpus/java/public/<source>/`。

独立索引验证：

```powershell
$env:OFFLINE_CORPUS_DIR='data/corpus/java/public'
.\.venv\Scripts\python.exe -c "from web.offline_service import build_index; r=build_index('data/corpus/java/public'); print(len(r), 'chunks')"
```

**踩坑（值得写进论文）**：第一次没过滤 `README.md`，问 `== 和 equals 的区别` 时首位命中是「README > 视频教程」——README 是目录页，把所有问题标题罗列了一遍，词面分数虚高。处理方式：抓取时直接跳过 `README.md`，并把 frontmatter 里的中文 `title` 提出来当 H1（否则章节路径会变成 `java-basic-questions-01` 这种英文文件名）。

### 5.2 代码语料实测（TheAlgorithms/Java）

| 指标 | 结果 |
| --- | --- |
| 下载 | 255 个 `.java`（数据结构 169 + 查找 30 + 排序 56），1.0MB |
| 切分 | **2169** 个片段，其中代码片段 1913 个 |
| 代码片段平均长度 | 1344 字符（上限约 1.5KB，未出现截断） |

这次实测发现两个真问题，都已修：

1. **符号抽取混入关键字**：初版把 `for`、`implements` 当成符号名。加了 Java 关键字黑名单，并在抽取前用 `_strip_comments()` 去掉注释——注释里 `// Node class representing each element` 会被正则当成方法声明，抽出 `representing`。
2. **跨语言检索是短板**：问「归并排序 mergeSort 怎么实现」，`MergeSort.md` 只排到 **第 8**（0.229），首位是 `SplayTree`（0.234）。原因有三：中文查询被切成单字，与英文代码没有词面交集；代码片段的上下文行（`【Java 代码】…结构：…`）把整文件符号名都列进去，反而稀释了词面分数；哈希向量对代码语义几乎无感。这是后续要专门做的「符号感知检索 / 查询扩展」的动机，也是论文可以讨论的局限。
