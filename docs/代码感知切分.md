# 代码感知切分（C1）

## 1. 要解决的问题

普通 RAG 按标题 / 段落切分，Java 讲义里的示例代码往往被当成普通段落处理：一个 30 行的类可能被从中间劈开，前半段缺类声明，后半段缺方法头，向量检索命中的片段读者看不懂，模型也无从回答「这个类怎么用」。

本模块把代码当作**结构化对象**而不是文本：围栏代码块整体保留，超长时只在类成员边界切开，并给每片补上上下文。

## 2. 处理流程

```
Markdown ──► parse_markdown_units  ──► 正文单元 ──► ChapterAwareSplitter（段落切分）
                    │
                    └─► 代码单元 ──► detect_language ──► extract_symbols
                                          │
                                          ├─ 不超长：整块保留 + 上下文行
                                          └─ 超长：split_java_code 按成员边界切分
```

1. **识别围栏块**：支持 ``` 与 ~~~，围栏长度可多于 3 个反引号，代码块内部的 `#` 标题不会被误判为标题。
2. **语言识别**：优先使用围栏标注（```java、```py），没有标注时按 `public class`、`System.out.print`、`def`、`=>` 等特征推断。
3. **结构提取**：正则提取 `class / interface / enum / record` 名称与方法名，作为 `code_symbols` 写入元数据，并在片段首行生成「结构：BigDemo、compute0…」。
4. **成员边界切分**：逐行扫描花括号深度（跳过字符串、字符与注释中的括号），在深度回到类体层级且行以 `}` 结尾处切开，保证每个片段都带类声明。
5. **上下文回填**：每个代码片段前置一行 `【Java 代码】课程｜章节路径｜结构：…`，让向量表示带上章节语义；切分后为多片时标注「片段 i/n」。

## 3. 新增元数据

| 字段 | 含义 | 示例 |
|---|---|---|
| `is_code` | 是否为代码片段 | `true` |
| `code_language` | 代码语言 | `java` |
| `code_symbols` | 结构符号列表 | `["ListDemo", "main"]` |

这三个字段随 `to_record()` 一起写入向量库，可在检索侧做「只搜代码」或「代码片段加权」的过滤与重排。

## 4. 效果对比

同一份讲义 `data/corpus/java/ch01-basics.md`，用 `scripts/compare_chunking.py` 跑两种切分：

| 策略 | 片段数 | 平均长度 | 围栏完整率 | 切断代码的片段 |
|---|---|---|---|---|
| 章节切分（基线，max_chars=600） | 9 | 377 | 67% | 3 |
| 代码感知切分（C1，max_chars=600） | 17 | 227 | **100%** | **0** |
| 章节切分（基线，max_chars=1200） | 7 | 469 | 100% | 0 |
| 代码感知切分（C1，max_chars=1200） | 16 | 231 | 100% | 0 |

结论：当切片上限小于示例代码长度时，基线策略会把 1/3 的片段切断；代码感知切分在任何上限下都保持围栏完整，并且平均片段更短、主题更集中。

复现：

```powershell
.\.venv\Scripts\python.exe scripts/compare_chunking.py --max-chars 600
```
