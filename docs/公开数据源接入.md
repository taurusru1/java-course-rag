# 公开语料接入：JavaGuide 与 TheAlgorithms

> 本文记录"把公开 Java 知识库接进系统"这件事的完整过程：怎么选源、怎么抓、
> 以及**为什么最终没有把两套语料混在一个索引里检索**。所有数字都在本机实测，
> 复现命令见第 9 节。

## 1. 为什么需要公开语料

自建讲义只有 4 章（基础语法 / 面向对象 / 集合与异常 / IO 流）、60 个片段，能回答的是
"多态是什么""数组长度能不能改"这类入门问题。但《Java 程序设计》课程真正会问的是
"HashMap 底层为什么用红黑树""AQS 的原理""JVM 有哪些垃圾收集算法"——这些内容
自建讲义里没有，只靠手写补课，工作量远超毕设周期。

公开知识库正好补这一块，代价是要处理两个问题：**许可**和**检索质量**。

## 2. 数据源与许可

| 数据源 | 许可 | 规模 | 结论 |
| --- | --- | --- | --- |
| [Snailclimb/JavaGuide](https://github.com/Snailclimb/JavaGuide) | Apache-2.0 | `docs/java` 61 篇 md / 1.56MB | **采用**：问答体，覆盖集合/JVM/并发/IO |
| [TheAlgorithms/Java](https://github.com/TheAlgorithms/Java) | MIT | 848 个 `.java` / 2.8MB | **仅实验**：纯代码，与概念问答几无重叠 |
| [itwanger/toBeBetterJavaer](https://github.com/itwanger/toBeBetterJavaer) | **无 LICENSE** | 899 篇 md / 14.4MB | 不接入：章节最像教材，但不能公开分发 |
| iluwatar/java-design-patterns | NOASSERTION | — | 不接入：许可不明 |
| byhieg/JavaTutorial | MIT | 165 java + 9 md | 备选：规模偏小 |
| vipstone/java-interview | Apache-2.0 | 236 star | 不接入：题目在 README 里，非结构化 |
| IAAR-Shanghai/CRUD_RAG | 无许可 | — | 不接入 |
| hendrycks/apps、google-deepmind/code_contests | MIT / Apache-2.0 | — | 不接入：英文竞赛题，不是课程问答 |

**合规处理**：抓下来的正文一律落在 `data/corpus/java/public/`，该目录已加入 `.gitignore`；
仓库里只提交抓取脚本与本文档，第三方内容不进公开仓库。JavaGuide 是 Apache-2.0，
即使入库也需保留版权声明，本地演示不涉及分发。

## 3. 抓取脚本

`scripts/fetch_public_corpus.py`（仅标准库，无第三方依赖）：

```bash
python scripts/fetch_public_corpus.py --source javaguide        # 抓 docs/java 下全部 md
python scripts/fetch_public_corpus.py --source algorithms       # 抓 .java 并在外面包 ```java
python scripts/fetch_public_corpus.py --list                    # 看已配置的数据源
```

要点：

- token 取 `GITHUB_TOKEN` 或 `gh auth token`。不带 token 会撞上 GitHub 的匿名限流
  （`HTTP Error 403: rate limit exceeded`），失败信息里能直接看到。
- **跳过 README.md**。第一次抓的时候没跳，结果问"== 和 equals 的区别"，
  第一名是「README > 视频教程」，得分 0.793——目录页把所有问题标题都列了一遍，
  词面重合度虚高。这是接入过程里第一个真 bug。
- 用 frontmatter 里的中文 `title` 当一级标题，保留原文的章节层级，切分才能按标题走。

## 4. 第一次实验：并库会淹掉讲义

最直觉的做法是把公开语料直接并进索引。实测（21 题讲义评测集）：

| 索引 | 片段数 | Recall@1 | Recall@3 | MRR | 要点命中 |
| --- | --- | --- | --- | --- | --- |
| 仅自建讲义 | 60 | **0.905** | 1.000 | 0.952 | 0.905 |
| 并入 JavaGuide + 算法 | 2989 | **0.381** | 0.476 | 0.464 | 0.429 |

讲义本来能答对的问题，被三千个扩展片段抢走了。原因不是检索算法坏了，
而是**规模差两个数量级**：词面打分只看"这题的关键词在不在这一段里"，
讲义里 60 个片段提供的匹配机会，远少于扩展语料里 2929 个片段。

## 5. 两条被否掉的补救方案

### 5.1 折减系数（失败）

给扩展语料的分数乘一个系数 `w`，等价于"讲义优先"。扫描结果：

| w | 1.0 | 0.8 | 0.6 | 0.4 |
| --- | --- | --- | --- | --- |
| A 组 Recall@1 | 0.381 | 0.524 | 0.667 | 0.857 |

w 越小越接近基线，但**永远回不到 0.905**；而且 w 越小，扩展语料越起不到作用。
两头不讨好，方案作废。

### 5.2 分数阈值分层（失败）

既然系数不行，能不能按"分数高低"判断答案来自哪一层？实测两组的分数分布：

- A 组（讲义能答的题）：讲义分支得分 0.55–0.73
- B 组（只有扩展语料才答得出的题）：讲义分支得分 0.17–0.70

**分布重叠**，不存在一个阈值能把两层分开。方案作废。

## 6. 最终方案：显式检索范围

既然算法分不开，就把选择权交给用户——这正是真实课程辅导系统的做法：
"先看教材，教材没有再看扩展资料"。

实现：

- 索引阶段给每条片段打 `source_tier`：路径含 `public` 记为 `extended`，否则 `textbook`。
- 检索接口 `retrieve_sections(records, query, top_k=8, tier=None)`，`tier` 非空时先过滤。
- 服务层 `scope` 三档：`textbook`（默认）、`extended`、`all`。
- 前端问答页两个 chip：「课程讲义」/「含扩展资料」，引用卡片按 `tier` 标「课程讲义」/「扩展阅读」。
- `public/algorithms` 默认不索引（`INDEX_PUBLIC_CODE=1` 才索引）：2169 个纯代码片段
  与概念问答几乎不重叠，去掉后 B 组要点命中率反而从 0.556 升到 0.667。

## 7. 结果

索引共 2989 个片段（讲义 60 / 扩展 2929）。

| 范围 | 评测集 | 片段 | 指标 |
| --- | --- | --- | --- |
| 课程讲义 | 21 题 | 60 | Recall@1 0.905 / Recall@3 1.000 / MRR 0.952 / 要点 0.905（**与接入前完全一致**） |
| 含扩展资料 | 12 题 | 2929 | 文件命中 0.750 / 要点命中 0.556（去掉代码片段后 0.667） |

分库之后，讲义范围的指标一个点都没掉，扩展范围拿到了 9/12 的文件命中。
这说明"讲义质量"和"扩展覆盖"可以共存，代价是用户要选一次范围。

## 8. 失败分析与负结果

B 组的三道失败题（p01 HashMap 底层结构、p02 JVM 垃圾收集算法、p04 AQS 原理）
是同一个病因：**兄弟概念小节的词面重合抢位**。

- 问 HashMap 底层，命中「HashMap 与 HashSet 的区别」那一节（因为反复出现 HashMap）；
- 问 JVM 收集算法，命中「JVM 面试题总结」的目录节（因为它把所有算法名都列了一遍）；
- 问 AQS，命中同章的「CyclicBarrier」小节。

试过、但没用上的两个办法：

1. **小节标题匹配奖励**：标题覆盖查询词就加分。w = 0.06 / 0.12 / 0.2 / 0.3 全扫一遍，
   文件命中率始终 0.750——只是把 p02 修好、把 p05 弄坏，属于"重排"而不是"改进"。
2. **代码片段降权**（接入前就试过）：概念问句对代码片段降权 0.05–0.3，指标不动。

顺带修掉一个真 bug：整节都是代码时（比如 AQS 那节），摘要抽句抽不到正文，
答案只剩「（说明：讲义中暂未讲到 aqs…）」。现在先取第一个有正文的小节，
全是代码时回退为「这一节主要是代码示例：…」。

## 9. 复现

```bash
# 1) 抓语料（需 gh 登录或 GITHUB_TOKEN）
python scripts/fetch_public_corpus.py --source javaguide

# 2) 重建索引并跑双库评测
python scripts/evaluate_public.py

# 3) 起服务后，问答页右上角切换「课程讲义 / 含扩展资料」
python -m uvicorn web.offline_service:app --port 9000
```

## 10. 局限与后续

- **扩展范围的文件命中 0.750 还可以再提**。当前词面打分对"术语分散在多个小节"的情况
  天生弱，下一步是 IDF 加权（把"HashMap""AQS"这类高频词降权），或者接真正的
  BGE-M3 向量（当前 128 维哈希向量对代码语义几乎无感）。
- **代码语料要不要进主库**仍是个开放问题：TheAlgorithms 的 2169 个片段对"看代码"
  有用，对"问概念"有害。可以考虑做成第三档 scope（只看代码示例）。
- **扩展语料不能进公开仓库**，答辩演示时要先跑抓取脚本，这一点写进了运行指南。
