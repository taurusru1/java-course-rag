# 检索评测方法与首轮结果

> 对应毕业论文第 6 章「实验与评测」。本文档记录评测集构造、指标定义、三组对照与失败分析，
> 数据可复现：`scripts/evaluate_retrieval.py` + `data/eval/java_qa.json`。

## 1. 评测目标

本课题的第一个可验证结论是：**代码感知切分（C1）产出的片段，配合混合检索，是否比朴素片段
+ 单一检索更容易命中「讲这道题的那一节」**。因此评测聚焦检索环节，先不牵涉生成质量，
把变量控制在「切分方式」与「打分方式」两个维度上。

## 2. 评测集构造

- 位置：`data/eval/java_qa.json`，共 21 条，三章各 7 条（1.x / 2.x / 3.x）。
- 每条样本三个字段：

  | 字段 | 含义 | 示例 |
  | --- | --- | --- |
  | `id` | 题号 | `q02` |
  | `question` | 学生会怎么问（口语化，不含答案要点） | `double 赋值给 int 需要强制类型转换吗？` |
  | `chapter` | 期望命中的小节号（检索目标） | `1.2` |
  | `keywords` | 一个正确答案必须出现的关键要点 | `["强制","截断"]` |

- 标注原则：`question` 只写学生自然提问，不抄教材原句；`chapter` 精确到小节，避免「同章任意
  片段都算对」；`keywords` 取该小节里**解释性文字**中的术语，用来近似判断「取回的片段能不能
  直接回答问题」。
- 局限：单标注者（本人），样本量 21，只覆盖三章语料；后续可扩到 60 题并请同学交叉标注。

## 3. 指标

| 指标 | 定义 | 回答的问题 |
| --- | --- | --- |
| Recall@1 | 第一名片段的章节路径包含目标小节的比例 | 能不能一次就命中 |
| Recall@3 | 前三名包含目标小节的比例 | 送进生成器的候选里有没有正确答案 |
| MRR | 目标首次出现位置的倒数均值 | 命中得靠前还是靠后 |
| 要点命中率 | 第一名正文包含该题全部 `keywords` 的比例 | 命中的片段是否**讲对了**（答案质量的代理指标） |

## 4. 三组对照

三种打分共用同一份索引（`data/corpus/java` 三章，**53 个片段**，由 `CodeAwareSplitter` 切出）：

1. **纯向量**：`HashingHybridEmbedder` 的 128 维哈希向量余弦相似度（基线，等价于「只有语义路」）。
2. **纯词面**：query token 与片段 token 的重合率（最朴素的词袋检索，等价于「只有 BM25 路」）。
3. **向量 + 词面（混合）**：`0.5 × 余弦 + 0.5 × 重合率`，与线上 `web/offline_service.py` 的
   `rank_hybrid` 是**同一份实现**，保证离线指标与线上行为一致。

### 4.1 结果（2026-11-11，21 题 / 53 片段）

| 策略 | Recall@1 | Recall@3 | MRR | 要点命中率 |
| --- | --- | --- | --- | --- |
| 纯向量 | 0.762 | 0.857 | 0.826 | 0.714 |
| 纯词面 | 0.619 | 1.000 | 0.809 | 0.714 |
| **向量 + 词面（混合）** | **0.809** | **1.000** | **0.905** | **0.857** |

### 4.2 解读

- 混合检索在 Recall@1、MRR、要点命中率三项上都是最优，说明两路信号互补：
  向量负责「换个说法也能找到」，词面负责「问什么就排什么」。
- 纯词面 Recall@3 也到 1.000，但 Recall@1 只有 0.619——候选里有答案，排序不够准，
  这也解释了为什么只做词面召回时学生会觉得「答非所问」。
- 纯向量 MRR 0.826 低于混合 0.905：语义路在中文短问句上区分度不足（哈希向量维度仅 128），
  把同章相邻小节排到了前面。
- 代码感知切分的价值不体现在这张表里（三组都用同一份 C1 索引），而体现在
  `docs/代码感知切分.md` 的切分对比：`max_chars=600` 时朴素切分有 3 片把代码块拦腰截断、
  围栏完整率 67%，C1 为 0 与 100%。

## 5. 失败分析

混合检索下要点未命中 3 条，均为「章节命中但排名第 2」：

| 题号 | 问题 | 现象 | 原因 |
| --- | --- | --- | --- |
| q02 | double 赋值给 int 需要强制类型转换吗？ | 第 1 名是 1.2 节的代码示例片段，未含「强制/截断」 | 示例代码与解释文字被切成两片，代码片段词面含 `double`/`int` 更高 |
| q19 | 自定义异常一般继承哪个类？ | 第 1 名是 3.6 节前一片段 | 3.6 节较长，异常示例与说明分属相邻两片 |
| q20 | 遍历时删除元素为什么会报错？ | 第 1 名是 3.7 节「越界」片段 | 3.7 节并列四种常见错误，词面互相干扰 |

三条失败指向同一个工程问题：**同一小节的多个片段之间缺少层级加权**。可行的改进是
「命中片段若与更高分片段同属一个小节，则合并上下文后再交给生成器」，这也是下一轮
（C4 完整对比：「纯 LLM / 向量 / 混合 + 重排」）要验证的点。

> 另记录一次负结果：曾尝试「问句不含代码特征时对代码片段降权 0.05–0.3」，
> 五档扫描下四项指标完全不变（R@1 恒为 0.810），说明当前失败与「代码片段挤占」无关，
> 故未采用该启发式，避免引入无依据的超参。
