# 编译报错诊断（创新点 C2）

> 对应毕业论文第 4 章「系统设计」的报错诊断子系统，与第 6 章「实验」中的诊断准确率。
> 代码：`scripts/collect_javac_errors.py`、`backend/.../service/DiagnoseService.java`；
> 数据：`data/errors/samples/*.java`、`data/errors/javac_errors.json`、
> `backend/src/main/resources/seed/error_cases.json`。

## 1. 为什么普通 RAG 做不好报错诊断

学生真实的困惑不是「什么是 NullPointerException」，而是把自己那 30 行堆栈贴进来问
「这行为什么错」。这类输入有三个特点，普通文档 RAG 都会翻车：

1. **文件路径、行号、变量名全是噪声**：切片检索会被 `DuplicateVariable.java`、`main` 这类词带偏；
2. **关键信息只有一行**：`错误: 需要在 main 里定义变量` 这一句决定了一切，其余是上下文；
3. **答案是确定的**：不是「可能因为…」，而是「这处改法只有一种正确写法」。

因此 C2 不走向量检索，而是**规则 + 案例库**的确定性链路，检索只作为兜底。

## 2. 链路

```
学生粘贴报错
   │
   ├─ 归一化：去文件路径 / 保留行号 / 保留错误摘要行
   │
   ├─ 案例匹配（DiagnoseService.match）
   │     对每个 ErrorCase：
   │       · 正则 javacPattern 命中 → 0.9
   │       · error_code 按 "_" 分词，全部出现在报错里 → 0.7
   │       · 都不中 → 0
   │     取最高分，< 0.5 视为未命中
   │
   ├─ 命中：返回 成因 + 修复步骤 + 最小示例 + 关联知识点
   │  未命中：写 DiagnosticRecord，提示转「课程问答」检索
   │
   └─ 落库 diagnostic_records(raw_error, matched_case_id, confidence, suggestion)
```

**为什么用「正则 0.9 / 关键词 0.7」而不是纯关键词**：同一个错误码在不同 JDK 与语言环境下文案
不同（中文 `找不到符号`、英文 `cannot find symbol`），正则能覆盖同义写法；但学生常把堆栈截断，
只剩错误类名，此时按 `error_code` 分词做关键词兜底，仍能命中。

## 3. 案例库结构

`backend/src/main/resources/seed/error_cases.json`（8 条，DataSeeder 启动时灌库）：

| 字段 | 说明 |
| --- | --- |
| `errorCode` | 稳定标识，如 `cannot_find_symbol`，前端与论文都用它 |
| `category` | 编译错误 / 运行时异常（前端按此分组） |
| `javacPattern` | 正则，必须同时覆盖中英文文案 |
| `cause` | 一句话成因（面向学生，不用术语堆砌） |
| `solution` | 分步修复建议，编号列表 |
| `exampleCode` | 最小可复现示例（3 行以内） |

把案例放在 JSON 资源里而不是硬编码在 Java 中，是为了让 **Python 采集脚本与 Spring Boot 播种
共用同一份词表**：`tests/test_javac_error_cases.py` 会用这份正则去匹配真实采集到的 javac 输出，
正则写错或漏了中文文案，测试直接失败。

## 4. 真实报错采集

`scripts/collect_javac_errors.py`：把 `data/errors/samples/*.java` 复制到临时目录，逐个
`javac -encoding UTF-8` 编译，捕获 stderr；编译通过的样例（运行时异常）再用 `java` 执行，
取异常首行。结果写 `data/errors/javac_errors.json`（8 条，6 编译 + 2 运行）。

### 4.1 踩到的坑：javac 输出不是 UTF-8

在中文 Windows 上 javac 的报错文本跟随**平台默认编码（GBK）**，而 Java 源文件是 UTF-8。
直接 `stderr.decode("utf-8")` 会得到 `����: �Ҳ�������`。脚本里按
`locale.getpreferredencoding(False) → gbk → utf-8` 依次尝试解码，并在文档里记下这一点：
**中文报错入库前必须确认解码方式，否则 RAG 会把乱码当语义**。

### 4.2 采集到的真实文案（节选）

| 样例 | 真实 javac / JVM 输出 | 归类 |
| --- | --- | --- |
| CannotFindSymbol | `错误: 找不到符号  符号: 变量 name` | cannot_find_symbol |
| IncompatibleTypes | `错误: 不兼容的类型: String无法转换为int` | incompatible_types |
| MissingReturn | `错误: 缺少返回语句` | missing_return_statement |
| DuplicateVariable | `错误: 已在方法 main(String[])中定义了变量 total` | duplicate_variable |
| MissingSemicolon | `错误: 需要';'` | missing_semicolon |
| NonStaticContext | `错误: 无法从静态上下文中引用非静态 变量 count` | non_static_context |
| NullPointerDemo | `Exception in thread "main" java.lang.NullPointerException` | null_pointer |
| ArrayIndexDemo | `Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException` | array_index_out_of_bounds |

## 5. 端到端验证

`scripts/smoke_diagnose.py` 把上述 8 条**原样** POST 到 `/api/diagnose`（UTF-8 编码，
带学生 token），结果：

```
ArrayIndexDemo         expect=array_index_out_of_bounds  got=array_index_out_of_bounds  conf=0.9
CannotFindSymbol       expect=cannot_find_symbol         got=cannot_find_symbol         conf=0.9
DuplicateVariable      expect=duplicate_variable         got=duplicate_variable         conf=0.9
IncompatibleTypes      expect=incompatible_types         got=incompatible_types         conf=0.9
MissingReturn          expect=missing_return_statement   got=missing_return_statement   conf=0.9
MissingSemicolon       expect=missing_semicolon          got=missing_semicolon          conf=0.9
NonStaticContext       expect=non_static_context         got=non_static_context         conf=0.9
NullPointerDemo        expect=null_pointer               got=null_pointer               conf=0.9
```

8/8 命中，且全部走正则（0.9）而非关键词兜底，说明 `javacPattern` 与真实文案一致。

> 注意：PowerShell 的 `Invoke-RestMethod` 在未声明 `charset=utf-8` 时会把中文 body 按
> Latin-1 发送，导致服务端收到乱码、只能退化成 0.7 的关键词匹配。**复现脚本必须用
> Python/显式 UTF-8 编码**，否则会误判「正则不生效」。
